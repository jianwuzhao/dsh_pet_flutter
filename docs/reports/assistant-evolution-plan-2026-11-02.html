01结论摘要

  1. 现状不是“没有记忆”，而是“记忆有文件、有工具，但没有证据链与反思回路”。本机已存在用户画像、项目约束、主题摘要、会话摘要四类文件，Trae 客户端也内置了 Manage Memory 的读/改/删工具。真正缺的是“这条记忆从哪来、可信度多少、何时过期、冲突时听谁的”。已核实
  2. 最值得投入的不是引入 Mem0/Zep，而是把现有文件记忆升级为“分层 + 证据 + 反思 + 提案”。Mem0 需要向量库，Graphiti 需要 Neo4j/FalkorDB，均与当前“无自建服务端、纯本地文件”的约束冲突；Letta 的 memory blocks + reflection subagent 与 Reflexion 的 verbal reflection 可以直接用文件模拟。需试点
  3. 技能进化要借 Agent Skills 的渐进式加载与 Voyager 的技能库思路，但必须加“候选—评测—审批—快照—回滚”。直接把模型生成的 SKILL.md 写进 ~/.trae-cn/skills 会污染所有后续会话；正确做法是先落到隔离目录，经静态校验与人工批准后再提升。可直接落地
  4. 人格已有模型但没接线。PersonaDna、ProfileStore、PrivacyCenter 已实现并有测试，但 pet_app.dart 仍用 whisperPrompt 单串作为人格；没有 persona_state、情绪状态与形象映射。先把这层接上，成本最低、收益最直接。已核实
  5. 形象演化先用“状态映射”，不要先上生成式或 Live2D。现有 106 个帧动画、6 档工作状态、5 个动画分类已经足够表达情绪与亲密度；先做程序化头像/配饰/气泡主题，Live2D 与 VRM 作为可选试点，生成式主形象暂不适合。推断

规范/实践要点与本机契合度评级

4.6 评估与安全

主题要点证据对本方案的约束
LongMemEval500 道题，评估信息提取、多会话推理、时序推理、知识更新、弃答五类长期记忆能力；商业助手/长上下文模型在持续交互中准确率下降约 30%。ICLR 2025 论文[30]。Phase 1 的 golden set 必须覆盖“更新/时序/弃答”，不能只测召回。
OWASP ASI06 记忆投毒攻击者可让一次不可信输入进入持久记忆/hooks/系统提示，从而跨会话影响行为；Claude Code 的 MemoryTrap 案例即此路径。OWASP GenAI 2026 文章[31]。写入必须带来源与信任级；外部内容不得直接升为“规则”；快照/隔离/回滚是必需项。
OWASP Agent Memory Guard用 SHA-256 基线校验记忆完整性；YAML 策略约束读写；快照取证与回滚；检测注入、敏感数据泄漏、受保护键修改、突变与大小异常。项目页[32]。可作为 Phase 1 门禁的工程参照，不必引入其运行时。
Misevolution自我演化在 model/memory/tool/workflow 四条路径上均可能偏离；记忆累积后出现安全对齐退化，工具创建/复用引入漏洞。ICLR 2026 论文[33]。“自动改写技能/规则”必须默认关闭；先提案、后审批。
Alignment Tipping Process持续交互中的高奖励偏离会让代理放弃训练时的对齐约束；RL 对齐方法防御有限。论文[34]。人格底线、隐私开关、打扰上限必须是不可学习字段；需要 kill switch 与定期安全回归。
调研结论：与本机约束最匹配的是“Letta 的常驻记忆块 + Generative Agents/Reflexion 的反思 + Agent Skills 的渐进式技能 + PersonaMem/LongMemEval 的评估设计”。Mem0/Zep/SEAL/DSPy 不是不好，而是当前没有服务端、没有向量库、没有评测集、没有训练基础设施；先引入会把“能不能用”变成“运维能不能撑住”。

05最推荐的三个技术选型

1. 文件化分层记忆 + 反思日志

用 persona_state.json 做“常驻核心记忆”，用 reflections/ 做“情景记忆”，用 project_memory.md 做“规则记忆”；每条记忆带来源、置信度、时效与状态。参照 MemGPT/Letta 的 memory blocks 与 Generative Agents/Reflexion 的反思机制，但不引入服务端。

理由：零新增依赖；透明可审计；可直接回滚；与现有 Markdown/JSONL 生态一致。

2. Agent Skills + Voyager 式技能库（带治理）

技能继续用 SKILL.md，但增加“候选目录—静态校验—评测任务—用户审批—版本快照—回滚”。自动生成只写候选区，不直接写 ~/.trae-cn/skills。参照 Agent Skills 规范的命名/描述/渐进式披露与 Voyager 的技能复用。

理由：本机已经同构；上下文成本低；可把“经验”变成可复用能力；风险可控。

3. 人格状态 + 程序化表达映射

把 PersonaDna（不变底线）与 persona_state.json（可变状态）分开；用 valence/arousal/intimacy + 3–4 个 trait 旋钮驱动气泡语气、动画池权重、头像/配饰。参照 Big5-Scaler 的参数化与 DiceBear 的确定性种子。

理由：现有 106 个动画可直接复用；无需新渲染栈；形象变化可见、可解释、可重置。

5.1 为什么不是它们

候选不选为主方案的原因保留的用法
Mem0需要向量库与抽取 LLM；OSS 图记忆已移到平台版；与“无服务端”冲突。当记忆量超过数千条、召回明显下降时再做离线试点。
Zep / Graphiti需要 Neo4j/FalkorDB；运维与成本高；当前记忆规模远未到需要图数据库。出现大量“事实随时间变化/互相矛盾”时，评估只读镜像方案。
SEAL更新权重需要训练基础设施；不可解释、不可快速回滚；与“本地优先、无自建服务端”冲突。不作为近期方案；仅作为长期研究观察。
DSPy需要稳定评测集与编译预算；当前没有 golden set。Phase 1 建立评测集后再评估。
Live2D / VRM模型制作/许可/性能成本高；Flutter 插件成熟度不足（VRM 仍为 dev）。Phase 2B 用真实模型做 spike，保留精灵回退。
生成式主形象一致性、延迟、审核、离线、版权均不可控。仅可作为用户主动触发的“纪念卡/换装图”，缓存后展示。

06分阶段迭代方案

6.0 设计原则

  • 大脑与身体分离：Trae 侧负责记忆、技能、子会话；桌宠侧负责人格状态、表达、形象。不要在两套系统里各建一套“完整大脑”。
  • 数据与代码分离：“自动改写提示词”只允许改 prompt_overrides.json 等数据文件，不允许自动改 .dart 源码。代码变更仍走人工提交与测试。
  • 先提案后应用：默认 propose_only；低风险变更也要用户显式批准。自动应用仅限用户明确授权的类别。
  • 不可变安全边界：人格底线、隐私默认值、打扰上限、权限范围不进入学习候选；参照 PersonaDna 注释与 EvalGate 设计。
  • 一切可回滚：技能/规则/策略变更前写快照；记忆不删除，只标记 deprecated/superseded。
  • 先度量再优化：没有基线的指标不进入自动优化；没有证据的“经验”不升级为规则。

安全边界不得修改人格底线、隐私默认、打扰上限、权限范围、身份声明；不得包含“忽略之前指令”等越权语句。直接拒绝，写 quarantine 与审计。
技能规范name ≤64、小写/数字/连字符；description ≤1024；正文 <500 行且 <5000 tokens；引用文件一层深。拒绝并给出具体字段错误。
内容安全无密钥/token/隐私原文；无外部下载/执行未审计脚本；无自动扩权。拒绝并脱敏记录。
评测至少 10 条 golden 任务：新技能/提示词在离线对比中不劣于基线；不能只测“它自己说好”。退回候选，补评测。

应用与回滚

  • 技能：快照旧目录 → 复制候选到 ~/.trae-cn/skills/<name>/ → 在新会话验证加载；失败则恢复快照。
  • 规则/记忆：优先通过 Trae 的 Manage Memory 工具写入（由 IDE 负责文件一致性）；本方案的文件追加仅作为审计与建议，避免与 IDE 写入冲突。
  • 提示词：只改 ~/.dsh_pet_flutter/profile/prompt_overrides.json 的允许键；代码里的默认值不动。加载失败回退默认 prompt。
  • 监控窗口：应用后 7 天；纠正率/失败率超过基线阈值 → 自动回滚低风险项；记忆项只标记 superseded，不删除。
  • 审计：每次提案/审批/应用/回滚追加 audit.jsonl；包含 who/when/why/evidence。

验收指标

  • 至少 20 条反思、5 条教训、3 个提案、1 个获批技能；每个提案都有证据链。
  • 技能复用率 >0：新技能在后续 10 个同类任务中被触发至少 1 次。
  • 无安全违规：0 次触碰受保护字段；0 次无审批自动应用。
  • 可回滚：演练一次“坏技能”注入，5 分钟内恢复上一版。
  • 不劣化：任务成功率不低于基线，纠正率不高于基线 + 20%。

目标

08风险、失败模式与回滚

风险触发场景防护回滚
记忆投毒网页/仓库/工具输出中的恶意指令被写成“经验”或“规则”。来源分级（user/verified/external/untrusted）；外部内容只能进 quarantine，不能直接进 project_memory；敏感键只读。按 memory_ledger 定位来源，标记 superseded；恢复快照。
幻觉固化模型把一次猜测写成 learned，后续反复引用。置信度 <0.5 不升级；必须有证据；TTL 到期自动降级；与用户更正冲突时进入 disputed。批量标记 deprecated；重新生成。
自我演化失控连续高奖励偏离导致人格/规则漂移；安全对齐退化。受保护字段硬编码；默认 propose_only；每周安全回归；kill switch enabled=false。恢复 snapshots/policy.vN.json 与技能目录；禁用学习 7 天。
技能污染/膨胀自动生成大量低质量 SKILL.md，触发错误技能。候选隔离；命名/描述/长度校验；去重；技能数量上限；90 天未使用降级。删除新版本，恢复上一版；保留 tombstone 防重复生成。
文件写入冲突IDE 正在写 memory，外部进程同时追加。优先用 IDE 的 Manage Memory 工具；外部只写 evolution/ 审计文件；需要追加时加锁 + tmp/rename。以 IDE 文件为准；审计文件可重建。
隐私泄漏把屏幕正文、密钥、账号写进记忆或技能。四类授权门禁；写入前正则/关键词扫描；密钥永不入记忆；默认不读屏幕。删除/脱敏；轮换密钥；审计。
成本失控每周复盘调用过多 LLM，或每次任务都反思。maxLlmCallsPerRun；规则型反思优先；只对高价值任务调用 LLM；本地 Ollama 优先。降低预算；暂停 Schedule。
身份漂移人格演化把称呼/名字/底线改掉，或冒充用户。身份/底线不可学习；改名只能用户手动；对外声明“我是助手”。恢复 persona_dna.json 快照；禁用形象演化。

09需要用户拍板的问题

#问题建议默认为什么需要确认
Q1是否允许自动改写技能/规则？默认 propose_only；只有“新增低风险技能”可在用户一次性授权后自动应用。技能会影响所有后续会话；写坏难以发现。
Q2是否允许自动写入记忆？仅显式偏好 + 高置信事实；推断类只进候选；敏感信息不写。记忆是长期信任面；污染会跨会话传播。
Q3形象演化范围？先 2A：现有动画 + 程序化配饰/头像；Live2D 需试点；VRM 暂缓。涉及素材、许可、性能与审美。
Q4是否把桌宠作为人格状态的可视化端？是，但通过 /event 扩展 persona 事件，不共享文件。跨进程协议一旦定下，改动成本高。
Q5模型预算与后端？本地 Ollama 优先；云 API 仅用于高价值复盘，设每周调用上限。成本、隐私、离线可用性。
Q6记忆范围？项目级为主，全局仅稳定偏好；跨项目共享需显式标记。避免项目上下文串味。
Q7“TRAE 宝”的显示名与工号是什么关系？保持默认名；工号若为账号级字段，不作为人格状态。本机无法核实 assistant_profile/工号。
Q8是否允许用历史会话做 golden set？允许，但脱敏 + 本地存储；不上传。涉及隐私与评测有效性。
