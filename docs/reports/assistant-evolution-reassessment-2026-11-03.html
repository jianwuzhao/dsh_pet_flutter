06最推荐的三个下一步技术选型

1. 记忆合并与证据层

在现有 MemoryEntry 上增加 confidence / evidence / updatedAt / lastUsedAt / supersededBy，写入时做归一化去重与合并，冲突时标记 superseded，而不是继续追加。参照 Mem0 的 consolidation、A-MEM 的 note evolution、Letta 的 memory block 整理。

理由：当前 4 条 pending 已出现近似重复；这是最便宜、收益最直接的质量修复。

2. 反思 → 技能/规则提案链路

新增 reflection.jsonl（任务结果、证据、根因、可复用动作），每周由 evolve-review 聚类成 lesson；再生成 SKILL.md 候选与规则补丁。所有候选先落隔离目录，经 Agent Skills 校验、评测、用户审批、快照后才进入 ~/.trae-cn/skills。

理由：这是用户目标“自主学习/进化”的核心缺口；Reflexion + Voyager + Agent Skills 三者能直接拼起来。

3. 形象全维渲染 + 自动触发

把 motionSet 接到 PoseMachine 权重、accessory 做成宠物本体叠加层、palette 加入演化步进；form 要么明确为“预览/头像”维度，要么新增精灵资源。自动触发放在状态终态/反馈后，保留 12h 冷却与冻结。

理由：当前状态模型已经完整，差的是“真的看见”和“自己会变”。

6.1 为什么不是它们

候选不选为主方案的原因保留的用法
Mem0 / Zep / Graphiti需要向量库/图数据库；当前记忆规模只有几十条，收益不足以抵消运维。当记忆 >1,000 条且召回明显下降时做离线评测。
SEAL权重自改需要训练基础设施；不可解释、不可快速回滚。长期观察，不进入近期路线。
DSPy / TextGrad没有稳定 golden set 与评分器；自动优化会过拟合。Phase 2 建立评测集后再评估。
Live2D / VRM模型制作、许可、性能成本高；当前精灵动画已能表达情绪。形象闭环完成后再做 spike。
生成式主形象一致性、延迟、审核、离线、版权不可控。仅做用户主动触发的纪念卡/换装图。

07下一步方案：先补质量，再谈进化

7.0 设计原则

  • 不要再建第二个大脑：桌宠内核与 Trae IDE 必须明确谁是任务主体。技能进化应落在 Trae 侧；桌宠侧负责人格、情绪、形象与本地记忆。
  • 质量优先于数量：记忆先去重/证据/冲突，再谈“更多记忆”；学习先有反思/评测，再谈“更多字段”。
  • 可见优先于复杂：形象先让 6 个维度真正被看见，再考虑 Live2D/VRM。
  • 一切可回滚：记忆标记 superseded，策略/技能保留快照，形象保留 10 版历史。
  • 数据与代码分离：自动演化只改数据文件（memory/policy/skill 候选），不改 .dart 源码。

目标

规则做法失败/回滚
去重同 kind + 同 subject + 归一化文本相似度高 → 合并 evidence，保留高 confidence/新者；不新增 pending。相似度阈值误合并 → 保留原始两条，标 disputed，让用户选。
冲突新偏好与旧偏好同 subject 且值不同 → 新条 active，旧条 superseded，保留 supersededBy。用户拒绝新偏好 → 恢复旧条（状态回 active）。
衰减 已实施✅ 已上线：MemoryStore.decay——episode >30 天、task >90 天、非 preference 闲置 >90 天（lastUsedAt ?? createdAt）→ archived 不再注入；preference 永不自动归档；注入上下文即更新 lastUsedAt；每天最多执行一次（启动 + 跨天维护）。归档不删除；用户可恢复/导出。
检索kind 优先级 + subject 匹配 + 新近度；可选本地关键词/BM25；仍保留 12 条/2000 字符硬上限。检索失败 → 空上下文，不阻塞对话。
损坏读取失败先备份 .corrupt，返回 Failure 并气泡提示；不再静默空库。用户可从导出文件恢复。

优先级状态问题影响建议
P0已实施反思信息太薄：当前只存 outcome + summary + source + taskId，没有 intent、动作、根因、验证结果。模型只能看到“构建失败”这类摘要，容易总结出泛泛而谈的经验。✅ ReflectionEntry 已扩展 intent / rootCause / verification（evidence 原有）；actions 与 run.progress 采集留待后续。
P0已实施触发条件粗：固定“3 条新反思 + 10 分钟”，一次高代价失败不会立即复盘。重要失败的经验可能延迟或被普通成功样本稀释。✅ 失败专用触发已上线：同 source 连续 2 次 failure 立即 force 触发（跳过 3 条门槛、保留 10 分钟冷却与并发闸）。
P0部分实施没有总结质量门禁：模型输出只过 JSON/越权过滤，没有 golden set、阴影运行或事实一致性检查。可能生成正确但无用的“正确的废话”，或把偶发事件当规律。🟡 事实一致性门禁已上线（正文 bigram 共现或 trigger 命中，否则丢弃）；golden set 与阴影运行仍待建。
P1已实施准则检索粗糙：只按 trigger 子串命中，最多 2 条；无相关度、时效、使用次数。准则变多后，真正相关的经验可能被旧准则挤出 prompt。✅ 关键词命中已排在“始终适用”之前；TTL/新近度排序留待准则规模上来后再做。
P1已实施语义去重不足：仅按归一化文本去重，模型换一种说法就会重复提案。pending 队列会被同义准则占据，增加用户审阅负担。✅ bigram Jaccard ≥0.6 二次去重已上线（归一化精确匹配之外）。
P1已实施没有有效性追踪：接受/停用只改状态，没有记录“采纳后是否减少同类纠正/失败”。无法判断准则是否真的让助手更聪明，也无法自动淘汰无效准则。✅ useCount/lastUsedAtMs 已上线（注入即记账，设置页可见）；采纳前后纠正率对照与自动建议停用留待数据积累。
P1已实施隐私与成本控制不足：任务摘要会发给当前 provider；无输入截断、token 预算或取消机制。长任务摘要可能包含敏感信息；总结调用增加成本与延迟。✅ 输入截断 4000 字符（保最近反思）已上线；memoryRecording 门禁维持；脱敏与 maxTokens/取消留待后续。
P2已实施准则没有版本恢复：只能停用，不能恢复到上一版 active 或查看变更历史。误接受/误停用后缺少可逆操作。✅ Guideline.history（accepted/archived/reactivated + 内容快照 + 版本）已上线；reactivate() 恢复已停用准则（版本 +1），设置页已停用列表提供“恢复”入口。
P2已实施只有任务终态驱动：没有日程/空闲时的主动复盘，也没有跨会话聚合。没有任务时不会学习；长期经验只能被动积累。✅ 日终复盘已上线：跨天首个任务终态若有 ≥2 条未总结反思（没凑满 3 条门槛的遗留）补一次总结，每天最多判断一次；仍“只提案、不自动应用”。真正的空闲定时触发待 Schedule 接入。
P2已实施prompt 级准则的边界：没有可执行步骤，无法验证准则是否被遵守。这是当前有意选择；但需要明确告知用户“软规则”，避免误以为它能执行动作。✅ system prompt 注入段已明确标注“软准则/倾向性建议/不是可执行动作”；设置页进化分区同步说明；未来若做技能库再引入 SKILL.md 与评测。

#问题建议默认影响
Q1谁是“TRAE 宝”的主体？桌宠内核（大肥鱼助手）还是 Trae IDE 里的 assistant？桌宠负责身体/人格/情绪/形象；Trae 负责任务与技能进化；两边明确边界。决定技能库、记忆库、日程任务建在哪一侧。
Q2是否允许自动合并记忆？低风险同 subject 自动合并；高影响（称呼/禁忌/隐私）只提案。影响记忆准确率与用户信任。
Q3是否允许自动改写技能/规则？propose_only；只有新增低风险技能可一次性授权自动应用。技能污染会影响所有会话。
Q4形象是否自动演化？是；12h 冷却 + 冻结 + 单步；form 仍提案。“自然变化”与“不要乱变”的平衡。
Q5form/accessory 是否要真实渲染？accessory 做本体叠加；form 明确为预览/头像，除非愿意新增精灵资源。决定是否需要新素材或 Live2D。
Q6PersonaDna/UserProfile 是否开放编辑？是；人格 Tab + 画像 Tab；底线只读。否则“个性化”只能改文件。
Q7provider 与 active adapter 谁优先？provider 可回复时本地对话优先；UI 明确写出，避免以为在跟 Trae 对话。影响投递体验与用户预期。
Q8是否允许用历史会话做 golden set？允许，脱敏 + 本地存储。决定评估是否可信。
Q9Live2D/VRM 是否进入近期路线？暂缓；先完成 6 维闭环。成本/许可/性能。
Q10是否修 DeepSeek 碎碎念路径？是；统一走内核 provider。当前是明确的代码不一致。
